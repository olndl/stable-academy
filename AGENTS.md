# Project notes

- Follow ROADMAP.md one day at a time. Don't implement later days unless requested.
- Before starting, read docs/progress.md and check git status.
- Use type/{short-name} for branch names and commit messages: feature/, fix/, test/, docs/, chore/. Keep messages short, in English, without attribution trailers.
- Use a pull request for each feature. Don't replace PRs with a local merge.
- Keep actual commit dates. Don't create future or backdated commits.
- Keep components small and avoid abstractions until there is a reason for them.
- Run lint, format:check and build before committing code. Add relevant tests as features arrive.
- Update docs/progress.md after each session. Record blockers as well as completed work.
- Product copy is in English. Planning notes can be in Russian.

- Keep the UI simple: system fonts, standard controls, plain layouts. No decorative graphics or marketing copy.
- Do not use Vercel unless explicitly requested again.
